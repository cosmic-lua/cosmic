## Change

Bump the board branch's `bin/cosmic.pin` to the release main already
pins, and regenerate `.cosmic-coverage` with the new toolchain — the
two land together because the gate cannot pass with either alone
(same shape as 3Ib5S8KI / PR #1505).

Measured 2026-09-02: the board's pin is
`https://github.com/whilp/cosmic/releases/download/2026-08-27-555873e/cosmic-lua`
/ sha256 145057b9fe905bb866fa3c03818265e4284a3bcd8367b76d9d5254f3c32a0900
(cosmos 2026.08.27-13977f2ef, Lua 5.4). At 555873e `_make/check.tl`'s
`check_files` calls `teal.check_file(f.path, ...)` raw (`git show
555873e:_make/check.tl`), while the compile step goes through
`_tool.seam` (`git show 555873e:_cli/build/work.tl` line 210). So under
this pin a runner-mode `*_test.tl` (D29) passes `--make ci` only if
`--make test` compiled it first (`check: 67 of 67 already proved by
their strict compile`) and fails cold with `warning: unused function
test_...` per case — reproduced on a copy of the board tree with
`_work/githold_test.tl`'s three self-call lines deleted: cold
`bin/cosmic --make ci` -> `check: FAIL (1 of 67 files)`, `ci: FAIL
(check)`; `--make test _work/githold_test.tl` then `--make ci` -> `ci:
PASS (4 stages)`. This is why #1607 had to self-call its cases against
AGENTS.md's "write new files in runner mode", and it is why every one
of the board's 34 `_work/*_test.tl` is still legacy-shaped. #1561
(c211a1e0, 2026-08-30) routed `check` through the seam; main's pin
`2026-08-31-a5b36f4` carries it (`git merge-base --is-ancestor a5b36f4
main`).

Under the NEW pin, a cold gate on the same tree copy: `fmt: PASS (67
files)`, `check: PASS (67 files)` (the runner-mode githold included),
`lint: PASS`, tests `34 checks: 34 passed` (the `_work` machinery runs

100.0% -> 95.9% (71/74, baseline 65/65)` — the newer coverage tool

The change, two files, nothing else:

## Non-goals

No `_work/**` changes ride along — `_work/githold_test.tl` stays
self-calling in this diff; converting the board's test files to runner
mode is the follow-on item blocked on this one. If the new toolchain's
gate refuses existing machinery CODE (any stage but the
coverage-baseline numbers), that is a bounce naming what broke, not a
fix-up here. `.cosmic-coverage` is written only by `--make coverage
--baseline`, never by hand.
