## Goal

G8 — the flow system. `skills/work/parallel.md` makes concurrent implementer
sessions the documented way of working, and `--make` is the project's one build
entry point. A build that corrupts a shared `o/` under that documented
concurrency, and can leave behind an artifact that reports success on nothing,
makes the flow system's own parallelism unsafe. It is also the anchor promise
inverted: a gate whose verdict is a lie is the silent bug the whole apparatus
exists to prevent.

## Evidence

Two `cosmic --make` invocations running against the SAME tree corrupt `o/` and
can leave `o/bin/cosmic` as a payload-less binary that silently behaves as bare
Lua — no verdict line, no error naming the cause, exit 0.

Observed 2026-08-17 in a planner session running board commands while a
sub-session ran its own `--make run` in the same checkout (`/home/user/cosmic`).
Three distinct failures, all from the same race, in this order:

```
make: cosmic-debug: error: failed to add 'sys/help.md' to zip: open source: No such file or directory
run: FAIL (cosmic failed)

make: cannot read o/cmd/cosmic/embed_gen/embed/cosmic/_version.lua: open ...: ENOENT (run build first)
run: FAIL (cosmic failed)

make: cannot clear o/cmd/cosmic/embed_gen: remove_all: .../o/cmd/cosmic/embed_gen: ENOTEMPTY: Directory not empty
run: FAIL (generate failed)
```

The tree was clean throughout (`git status --porcelain` empty, `sys/help.md`
present), so every one of those messages names a missing input that exists — the
other process was mid-write in the directory this one was reading.

The dangerous outcome is the fourth state, not these three. After one such race
`o/bin/cosmic` existed, was executable, was 8.2 MB, and had NO embedded payload:

```
$ o/bin/cosmic --make run _work/board.tl status
usage: o/bin/cosmic [options] [script [args]]     # bare Lua's help
$ echo $?
0
$ o/bin/cosmic --version
o/bin/cosmic: unrecognized option '--version'
```

Exit 0 with Lua's usage text on stdout. Anything reading that as a verdict — a
recipe, a script, a session grepping for `PASS` — sees a successful run of
nothing. The earlier symptom of the same corruption was `module 'cosmic.searcher'
not found` with a `/zip/` traceback, which at least fails loudly.

Why this is worth a card and not just operator discipline: `--make` is the
project's one build entry point, parallel implementer sessions are the documented
way of working (`skills/work/parallel.md`), and the failure mode is a binary that
reports success. Candidate shapes for the fix: an exclusive lock on `o/` for the
duration of a build (refusing or waiting, with a message naming the holder), or
making the staged binary appear atomically (build to a temp path, rename into
`o/bin/`) so a concurrent reader never sees a half-written artifact. The second
also fixes the reader side, which the first does not.

Related but distinct: #1212 (COSMIC_MAKE_ROOT leaking into spawned test children
in nested worktrees) is about one build's environment reaching another; this is
two builds sharing one output directory.

## Refinement notes

Two questions the refinement pass must settle, both measured rather than
asserted:

1. **Which of the two shapes, or both.** The lock and the atomic rename close
   different halves — the lock serialises writers, the rename protects readers.
   The reader half is what produced the exit-0 artifact, so a slice that ships
   only the lock leaves the dangerous state reachable by any reader racing a
   build that is not itself under the lock (a stale `o/bin/cosmic` from a killed
   build, for instance). Read `_make/` and state which files own staging and
   installation before picking.
2. **What a payload-less binary should do.** Independent of the race: the
   artifact's own entry point can assert its payload is present and fail loudly
   with a verdict line instead of falling through to bare Lua's argument
   handling. That is a separate, smaller, independently verifiable slice, and it
   is the one that converts every future instance of this class from silent to
   loud. It may well be worth cutting out and landing first.

## Refined to ready, 2026-08-19 — the shape questions, measured and settled

**The install is already atomic.** `_make/artifact.tl`'s
`replace_if_changed` (line 420) stages every binary to `<out>.new` and
swaps it in with `fs.move` — a same-directory rename. The exit-0
artifact was therefore NOT a half-written file: the racing build
half-cleared the STAGING DIRECTORY between `stage()` and
`embedc.write` (line 465), so a well-formed zip with missing payload
was assembled and then atomically installed. Atomicity cannot help
when the content is wrong — the missing piece is verification.

**This item is the verify-before-install slice.** The writer-side lock
(serializing concurrent `--make` runs, which also kills the three loud
ENOENT/ENOTEMPTY races in the Evidence) is filed separately with its
own measured constraints — notably that `cosmo.unix` has NO `flock`
(probed 2026-08-19: `u.flock` is nil), so it is an O_EXCL-lockfile
design and a bigger diff. This slice alone converts the DANGEROUS
state — success reported on nothing — into a loud build failure.

## Change

In `_make/artifact.tl` (499 lines), `build()` (line 443):

1. Extract a testable checker:
   `verify_payload(path: string, expected: integer): string | nil` —
   open `path` with `cosmic.zip` (read mode), `list()` it, return an
   error string unless `main.lua` is present and `#entries ==
   expected`. Probed 2026-08-19 against a built cosmic: `zip.open` +
   `list()` reads an APE artifact's payload directly (554 entries,
   `main.lua` found), so the check needs nothing outside the box.
2. Call it between `embedc.write` (whose return `count` is the
   expected entry total) and `replace_if_changed`: on failure, remove
   `staged_out` and fail the build with a message naming the artifact,
   both counts, and the likely cause — another `--make` mutating this
   tree — so the operator learns the reason, not just the symptom.
3. Export `verify_payload` through the module record for the test.
4. **Tests** (`_make/artifact_test.tl`): build a small zip with
   `cosmic.zip` containing `main.lua` and one module → verifies at the
   right count, fails at the wrong count; one WITHOUT `main.lua` →
   fails naming it. No race simulation — the checker is pure and the
   race's product (a payload-light zip) is exactly what the fixtures
   construct.
