## Goal

G1&#39;s anchor promise — no silent bugs, &#34;documented behavior is verified
behavior&#34; — applied to the build&#39;s own gates. A test whose inputs are invisible
to the dependency graph is never invalidated, so its PASS is replayed from cache
rather than measured. The gate reports green about a tree it did not read.

Third instance of this exact class, which is why it is filed as a countermeasure
rather than a one-file fix:

- #1156 — fuzz acceptance is vacuous: `--make test` replays a cached result when
  only the environment changed.
- #1178 — `_build/env_vars_test.tl:2`&#39;s eleven-token `--- reads:` line parses as
  nothing, so the test never re-runs.
- **This one** — `_perf/perf_test.tl` declares no `reads:` at all.

## Evidence

`_perf/perf_test.tl` is the smoke test that loads every bench module and asserts
every scenario carries a functional check. It derives its module list rather than
hardcoding it, deliberately (`_perf/perf_test.tl:6-8`):

```teal
local paths, err = fs.glob(BENCH_DIR, &#34;*_bench.tl&#34;)
...
local stem = fs.split_extension(fs.basename(p))
```

so every `require` is computed and no `_perf/bench/*` path appears in its import
closure:

```
$ grep -c &#39;reads:&#39; _perf/perf_test.tl
0
$ grep -o &#39;_perf/bench[^ ]*&#39; o/project.mk | grep -c &#39;srcdeps__perf/perf_test&#39;
0
```

`srcdeps__perf/perf_test` carries 17 deps and none of them are bench modules. A
bench-only diff therefore cannot invalidate this test&#39;s cached PASS.

Observed live on PR #1195 (issue #1192), which rewrote 51 cast sites across 16 of
the 17 bench modules. The `ci` job on head `c0b39f6` completed in **52 seconds**
and reported `ci: PASS (5 stages)`. The four `.cosmic-coverage` rows the PR
committed carry `covered` byte-identical to main while `total` rises:

```
                              main        PR #1195
_perf/bench/fs_bench.tl       97 106      97 129
_perf/bench/json_bench.tl     66  76      66  89
_perf/bench/micro_bench.tl   110 120     110 138
_perf/bench/startup_bench.tl  73  85      73  98
```

An unchanged `covered` across a diff that adds executed lines is the signature of
a file that was never re-measured. The honest numbers, measured on a cold tree,
are `102 116`, `73 88`, `119 138`, `76 94` — `covered` rises in every case.

The tree already contains the working pattern and the broken one side by side:
every declaring test lives in `_build/`, and `_build/snippets_test.tl:2-15` uses
the one-path-per-line form that parses, while `_build/env_vars_test.tl:2` uses
the single-line multi-token form that does not (#1178).

## Proposed countermeasure

Core, per `enable.md`&#39;s ordering — a lint, so it transfers to every future test
rather than to whoever reads this issue.

A `*_test.tl` that reaches the filesystem for its inputs must declare what it
reads. The lint&#39;s trigger condition is the design question to settle during
refinement; the cheapest honest version flags a `*_test.tl` that calls a
filesystem-enumeration primitive (`fs.glob`, `fs.walk`, `fs.find`, `fs.ls`) or a
computed `require` while carrying no `--- reads:` declaration. That is a
syntactic check the existing pure-lint pass in `_tool/` can host.

The alternative — inferring reads dynamically from what the test process actually
opened — is stronger but much more machinery; a refiner should price both and say
which. Note that a lint here composes with #1178: that issue makes the
declaration parse, this one makes its absence detectable.
