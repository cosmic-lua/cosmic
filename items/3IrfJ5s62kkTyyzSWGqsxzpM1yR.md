## Change

Bump the `board` branch's `bin/cosmic.pin` to a release whose embedded
`_make/policy.tl` carries the `COSMIC_COVERAGE_ENV` baseline-refusal
guard, and regenerate `.cosmic-coverage` under it in the same commit —
mirroring `WA0n_8XRm` (PR #1505)'s shape for an earlier pin-staleness
gap.

Measured 2026-09-04: the board's pin is
`2026-08-31-a5b36f4` / sha256 `c02f8b1c77cd81489d13765d18578b9a2a08ad9d7f3744cfdee81c070837e1b5`;
that release's embedded `_make/policy.tl`
(`unzip -p o/bootstrap/cosmic .tl/_make/policy.tl | grep -n
"COSMIC_COVERAGE_ENV\|is_recording_env\|REFUSED"`) matches nothing —
`write_baseline` runs unconditionally. Reproduced: in a clean `board`
worktree with `COSMIC_COVERAGE_ENV` unset, `bin/cosmic --make coverage
--baseline` exits 0, prints no refusal, and rewrites 15 of 16 rows of
`.cosmic-coverage` (3 lowered, 12 raised), none touched by any pending
change.

main's pin is `2026-09-04-f9f31a2` / sha256
`81c372373529f4d011e31e9df58dc331c495eba283d788438af47302162c06ce`
(verify this is still main's current pin at pull time — it moves
daily; if it has moved, use whatever main's pin is then, provided its
release still carries the guard per the check below).
`git show origin/main:_make/policy.tl | grep -n
"COSMIC_COVERAGE_ENV\|is_recording_env\|REFUSED"` on that commit
returns `is_recording_env()` (checks
`os.getenv("COSMIC_COVERAGE_ENV") == "1"`) and the
`"coverage --baseline REFUSED: ..."` string — this pin's release

The change, two files, nothing else:

1. `bin/cosmic.pin`: url line
   `url = https://github.com/cosmic-lua/cosmic/releases/download/2026-09-04-f9f31a2/cosmic-lua`,
   sha256 line
   `sha256 = 81c372373529f4d011e31e9df58dc331c495eba283d788438af47302162c06ce`
   — both fields together (or the equivalent pair for whatever main's
   pin is at pull time, re-measured).
2. `.cosmic-coverage`: regenerated by the new toolchain itself — after

   same marker is in keeping with the guard rather than working around
   it) — committed as the tool wrote it, never edited by hand. Read the
   regenerated rows against the old file: every module present before
   must be present after (a VANISHED row is a bounce, a re-measured
   number is not).

After landing, confirm the fix: in a fresh `board`-branch worktree,
`bin/cosmic --make coverage --baseline` run with `COSMIC_COVERAGE_ENV`
UNSET now prints `coverage --baseline REFUSED: ...`, exits non-zero,
and leaves `.cosmic-coverage` byte-identical (`git diff` empty).

## Access

Read access to `cosmic-lua/cosmic` (the release asset the new pin
names, and `main`'s `bin/cosmic.pin` it is copied from). Nothing is
written to any repository other than this one; the PR lands on this
repository's `board` branch.

## Non-goals

Not a general coverage-tooling audit — scoped to this one pin bump and
its regen. Not implementing a second copy of the guard anywhere in the
`board` branch's own tree — there is nowhere to put one: the branch
owns no `_make/`, no `cmd/cosmic`, no coverage-policy source of its
own; the guard reaches `board` only via `bin/cosmic.pin`.
