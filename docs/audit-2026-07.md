# cosmic Codebase Audit & Remediation Plan

**Date:** 2026-07-03
**Commit audited:** `f91e36c`
**Goal:** advance cosmic toward its stated mission — a *complete, safe, performant, portable, batteries-included* Lua/Teal programming suite — by cataloguing functional and usability gaps, test and documentation weaknesses, portability and performance risks, and places where the boundary between the typed Teal layer and the upstream Cosmopolitan C bindings is drawn incorrectly, and by sequencing the work to fix them.

This document is the output of a full-codebase audit spanning six dimensions: API completeness, test quality, documentation, the Teal↔C boundary, safety/correctness, and portability/performance. Findings are consolidated here with concrete file:line evidence and a phased remediation plan. Severities: **P0** ship-blocking / correctness / security, **P1** high user impact, **P2** meaningful gap, **P3** polish.

---

## Executive summary

cosmic is in good architectural shape. The build system, sandbox story (landlock/quicksand), documentation *pipeline*, and the code-generation of C type definitions are genuinely strong, and the error-handling convention is followed in most modules. The audit nonetheless surfaced a coherent set of systemic issues that, fixed together, would materially raise quality:

1. **A single root defect drives two whole classes of bug.** The generated `lib/types/cosmo/unix.d.tl` declares an `Errno` return on only ~23 of ~198 syscall functions. Every wrapper that wants error detail must cast (`as(boolean, any)`); every wrapper that doesn't cast **silently cannot see the error and swallows it**. The true source is upstream: the generator faithfully reflects the LuaLS annotations shipped in Cosmopolitan's `definitions.lua`, which omit the error return. **Because we control the `whilp/cosmopolitan` fork, the clean fix is to add the annotations upstream** so the generator emits `, Errno` naturally — removing ~hundreds of casts *and* unblocking consistent error reporting across the whole stdlib, with no in-repo post-processing hack.

2. **Error reporting is inconsistent to the point of being unreliable.** Four different conventions coexist (`errno:doc()`, `tostring(err)`, silently-swallowed generic strings, and `-1` sentinels). `fs_ops.tl` swallows errno in all 16 of its functions while importing `Errno` unused. Programmatic error handling (retry on `EAGAIN`, create-on-`ENOENT`) is impossible through the typed API today.

3. **Several correctness bugs violate the project's own "never throw / never swallow" rule** — notably SQLite iterators that hide step errors as end-of-results (silent data loss), `time.timegm` throwing on malformed input, and closed-socket methods throwing instead of returning `nil, err`.

4. **Security posture is mostly strong but has real fail-open holes** — quicksand's `capabilities().pledge/unveil` are effectively always `true`, a malformed proxy-allowlist port silently widens to "any port", and `landlock.RW` silently includes EXECUTE.

5. **Portability is asserted but untested.** CI runs on Linux only; the five non-Linux fat-binary targets ship daily with zero automated testing, and `welcome.tl` mutates the running binary (breaking release checksums and repeating forever on Windows).

6. **The suite is missing headline batteries** — no HTTP server, no application logging, no HMAC, no `fs.copy`/`move`, a very sparse `string` module, and a `time` parser that rejects fractional-second ISO-8601.

7. **Tests bypass the layer they test.** 43 test/example files import `cosmo.*` directly for setup/teardown, so the wrappers' own paths get no dogfooding, and the ban is unenforced by the linter.

8. **Documentation coverage is bimodal.** Sandbox modules are exemplary; the entire socket API (17 methods) and the flagship SQLite methods (`db:query`, `db:exec`) have zero doc comments, there is no root `README.md`, no install instructions, and published docs reference a `fetch.get` API that does not exist.

### Owner steering decisions (2026-07-03)

These are deliberate directional calls by the maintainer that govern how the findings below are sequenced and framed. They are the "why this order" behind the phased plan.

| # | Decision | Choice | Rationale / accepted tradeoff |
|---|---|---|---|
| **D1** | **Primary axis** | **Boundary/foundation first, then the rest.** | The boundary defect is *causal*: fixing the Teal↔C layer first means test build-out pins down already-correct error contracts (not soon-to-change behavior) and new batteries build on typed, errno-honest bindings. Tradeoff: the first *externally visible* win (batteries, docs) lands after the foundation — a bet that correctness compounds faster than adoption pressure pre-1.0. |
| **D2** | **Upstream sequencing** | **Block on upstream, do it right** (see Phase 0). | Land U1–U3 in the fork and bump `cosmos` *before* in-repo cleanup, so each cast is touched once. Tradeoff: the program is serialized behind fork turnaround — safe only while we own the fork's release timing. Break-glass: the in-repo shim (§1.1) if upstream slips past ~2 weeks. |
| **D3** | **Security vs. axis** | **Hold the line — security fixes sit in Phase 1**, after the foundation. | Discipline over urgency; most holes require an attacker *already inside a box* or a *corrupt/contended* DB. **Condition:** this holds only if nothing in production currently relies on quicksand to contain untrusted code. If that condition fails, `landlock.RW`⊃EXEC (§2.3) and the proxy allowlist widening (§2.3) — both sandbox-weakening and independent of the foundation — jump to an immediate hotfix. |
| **D4** | **API compatibility** | **Break freely — pre-1.0, no compatibility guarantees.** | Fix return shapes correctly (errno consistency, SQLite iterator, `-1` sentinels, `Fetch` rename); update in-repo callers in the same PR. Two consequences baked into the plan: (a) the **cosmo-ban test migration (§1.7) is pulled forward** ahead of the breaking changes — tests that set up through `cosmo.*` won't fail when a wrapper's shape changes, so they must be migrated *before* the shapes change or breaks go uncaught; (b) keep a running CHANGELOG / migration-notes file so anyone tracking `main` can adapt. |
| **D5** | **Document role** | **Exhaustive backlog of record.** | Optimize for completeness and traceability — nothing is dropped. **Phases express order, not scope:** every finding stays in scope over time and is tracked to completion, referenced by stable handles (`§x.y` section numbers, `U#` upstream IDs). No "if you only do N things" cut line. |
| **D6** | **Batteries scope** | **Match reference stdlibs (breadth), sequenced by upstream leverage.** | Completeness is the promise — aim for parity with what a Python/Go developer expects built in — so nothing is *hard-excluded* (the previously-"skip" long tail in Dimension 4, e.g. bignum/decimal, semver, WebSocket, MIME, moves in-scope to Wave 3, not out). But batteries are ordered into three waves by how much Cosmopolitan already provides (Phase 4): **Wave 1** declares/wraps C already in the binary (near-free, most-correct — overlaps the U8 audit); **Wave 2** is pure-Teal over existing primitives; **Wave 3** is net-new surface / new C work. `httpd` is deferred to Wave 3, but when built it exposes redbean's HTTP C (`ParseHttpMessage`/`GetHttpHeader`/…) from the fork and thin-wraps it in Teal — *not* hand-rolled HTTP/1.1 parsing. |

The plan below is organized into phases that front-load the highest-leverage, lowest-risk fixes (the upstream annotation/binding work, the errno helper, the security holes, the correctness bugs) before the larger additive work (new modules, test build-out, docs). Per **D5**, the phases are an execution *order*, not a scope boundary — everything catalogued is in scope.

> **Where a fix belongs.** We control both this repo *and* the upstream `whilp/cosmopolitan` fork (the C bindings, the `cosmos` binary, and its LuaLS `definitions.lua`). Findings whose cleanest fix is at the source are tagged **`[UPSTREAM]`** inline and consolidated in the **Upstream remediation** section (just before the phased plan). The rule of thumb: if a cosmic wrapper is casting around a missing/wrong *declaration*, or hand-rolling in Teal something the C layer could do (or a binding is simply absent), prefer fixing upstream over papering over it here — a wrong declaration fixed upstream deletes the workaround everywhere at once, whereas a generator hack or a local cast has to be maintained forever.

## Dimension 1 — Teal ↔ C boundary

The boundary is where the most leverage is: one generator change cascades into many modules.

### 1.1 The missing-`Errno` root defect (P0)

- `lib/types/cosmo/unix.d.tl` has 204 `function` members; only ~29 mention `Errno` in a return type (≈23 real API functions). At runtime nearly every `unix.*` call returns `nil|false, unix.Errno` on failure.
- Functions declared **with** Errno: `open`, `close`, `write`, `fork`, `execve`/`execvp`/`execvpe`/`fexecve`, `setresuid`/`setresgid`, `socket`, `bind`, `listen`, `connect`, `recv`, `send`, `sethostname`, `unshare`, `setns`, `pivot_root`, `sigsuspend`, `tcgetattr`, `tcsetattr`.
- Functions **missing** it (spot-verified): `mkdir:1134`, `makedirs:1141`, `mkdtemp:1149`, `chdir:1162`, `rmdir:1170`, `readlink:1188`, `realpath:1191`, `getcwd:1242`, `stat:2293`, `fstat:2318`, `opendir:2340`, `read:804`, `pipe:1039`, `kill:1107`, `killpg:1114`, `setrlimit:2060`, `setpriority:2088`, `setsockopt:1771`, `shutdown:1943`, `getsockname/getpeername:1907/1911`, `sendto/recvfrom/accept/socketpair/getsockopt`, `setuid/setgid/setfsuid/chroot:1414/1419/1416/1394`, `pledge:2219`, `unveil:2262`.

**Fix `[UPSTREAM]` (preferred):** add the `Errno` (and `nil`/`false` failure) return to the LuaLS annotations for fallible functions in the fork's `definitions.lua`, so the generator emits `, Errno` naturally on regeneration. This is the highest-leverage single change in the audit — it fixes the declarations at the source, keeps `gentype` a faithful translator, and deletes the `as(boolean, any)` casts across `lib/cosmic` once and for all. **Fallback (in-repo, if an upstream turnaround is undesirable for some functions):** a post-processing table in `lib/types/gentype_render.tl` that appends `, Errno` to a known list of fallible `unix.*` functions — carries an ongoing maintenance cost and can drift from upstream truth, so use it only as a bridge. Either way, then delete the now-redundant casts.

### 1.2 Concrete wrong declarations (P1)

All of the generated-file items below originate in upstream annotations and are best corrected in `definitions.lua` **`[UPSTREAM]`** (the `cosmo.d.tl` item is hand-written in-repo). Fixing them upstream removes the corresponding in-repo casts on regeneration.

- **`[UPSTREAM]` `fdopendir` (unix.d.tl:2345)** — ✅ resolved 2026-07-04 ([cosmopolitan#131](https://github.com/whilp/cosmopolitan/pull/131) + `cosmos` bump in [cosmic#431](https://github.com/whilp/cosmic/pull/431)): the annotation now declares a single `unix.Dir` return (matching `opendir`), regen makes `fdopendir: function(fd: number): Dir, Errno`, and the `fs.tl` wrapper mirrors `opendir` with no cast + gained tests. *(original finding preserved — note the realized bug was worse than described: on **success** the binding returns one self-iterating Dir, so `_, raw` left `raw` nil and the wrapper errored on every good open.)* Declared `function(fd?: any): function, Dir` — `fd` is neither optional nor `any`, and there is no error return. This shaped a **probable runtime bug** at `fs.tl:247-253`: `local _, raw = unix.fdopendir(fd)` keeps the *second* return; on failure `fdopendir` returns `nil, Errno`, so `raw` is a **truthy Errno**, the `if not raw` guard passes, and `make_dir(raw)` yields a "Dir" whose `read()` throws — violating never-throw. (The in-repo `fs.tl` guard should also be hardened, and `fdopendir` is called nowhere so it is wholly untested.)
- **`[UPSTREAM]` `setenv`/`unsetenv` (unix.d.tl:835,842)** all-`any`, all-optional; should be typed `string`.
- **`[UPSTREAM]` `Stat.nlink/gen/flags` (unix.d.tl:284-286)** typed `any` (the generator couldn't parse the upstream annotation); `fs_types.tl:54` quietly re-asserts `nlink` as `number`. Fix the annotation upstream (and/or teach `gentype` to parse the shape).
- **`[UPSTREAM]` `siocgifconf` (unix.d.tl:1595)** returns `any`; `net.interfaces` casts the blob straight to `{Interface}` with no validation (net.tl:277). A typed return upstream removes the cast.
- **`cosmo.d.tl` (hand-written, in-repo) is systematically lossy:** `Barf(...): boolean` and `Slurp(path): string` (lines 17-18) drop the real `nil, Errno` failure returns; `Fetch`/`FetchStream` take untyped `opts?: {string:any}`; `EncodeLua` hides that it can raise on cycles/depth (`doc.tl:395,404` call it bare); **`[UPSTREAM]`** no `DecodeHex` is declared though `EncodeHex` is — and if the *binary* lacks a hex decoder, add one upstream — forcing pure-Teal per-byte hex decode (codec.tl:25-31).

### 1.3 Record duplication instead of reuse (P2)

The escape hatch of choice is not `as any` (only 2 in the whole non-test tree) but **re-declaring the C record locally and casting into it**:
- Four Stat-shaped records: `unix.Stat` (15 methods), `fs_types.Stat` (drops `ino`/`blksize`/`gen`/`flags` — and `ino` is needed for the rename-swap detection unix.d.tl's own docs describe), `fs_types.WalkStat`, plus the walk contract.
- `errno.tl.Errno` duplicates `unix.Errno` but **drops `__tostring`** (so `tostring(err)` paths only type-check because `err` is untyped).
- `sqlite.tl:22-51` declares `RawStatement`/`RawDatabase`/`RawSqlite3` and casts the properly-typed generated `lsqlite3.d.tl` *into its weaker duplicate*.
- Also `RawDir` (fs.tl:19), `Sigset`/`Rusage`/`Memory`/`Termios` duplicated in signal/proc/shm/tty.

**Fix:** import the generated records (already on the compiler include path) and reserve local records only for genuinely *narrowed* public surfaces, documenting what is intentionally dropped.

### 1.4 Cast hotspots (P2/P3)

~809 `as`-cast grep hits in non-test sources (upper bound). Worst files: **signal.tl 57** (of which ~49 are gratuitous `as number` on already-`number` constants, lines 234-289 — delete them), **quicksand/box/run.tl 42** (from `run.tl:33 local u = unix as {string:any}` discarding all typing on the most safety-critical code path), **doc.tl 29** (Lua integer/`string.find` friction, not a boundary issue), **landlock.tl 20** (flag constants typed `number` but used in bit-ops — **`[UPSTREAM]`** best fixed by annotating integer constants as integers in `definitions.lua`, or in the generator by emitting `integer` for integer-valued constants), proc.tl 14, ip.tl 14, time.tl 13.

### 1.5 Leaky / thin abstractions (P2)

- Three different fd-exposure conventions: `net.Socket.fd` public field vs `io.Handle:fd()` method vs `child.Pipe.fd` public vs `poll` raw fd numbers.
- Raw cosmo userdata crosses the public boundary: `Rusage` method-objects (`child.wait`, `proc.getrusage`), `shm.Memory`, raw `wstatus` ints requiring `WIFEXITED`, and `proc.execve*` returning a raw `Errno` **object** in the string slot (so `err .. "..."` misbehaves and `if err` is always truthy).
- Wrappers hide C options they should pass through: `net_socket.send` drops the `offset` param (unix.d.tl:1930); `net.listen_tcp` hard-codes `SO_REUSEADDR` with no opt-out/`SO_REUSEPORT`; `shm` exposes no `munmap` (mapping can never be released); `tty` `restore` is always `TCSANOW`.
- `pledge.tl`/`unveil.tl` are single-function passthroughs that **hide `unix.pledge` mode flags** — callers must reach back into `cosmo.unix` for them, forcing exactly the boundary violation the wrapper exists to prevent. Enrich with promise/mode constants and a self-documenting `unveil.commit()` (today it's the raw `apply(nil, nil)` footgun), or fold pledge/unveil/landlock into one `cosmic.sandbox` namespace.

### 1.6 Wrong-layer logic (P2/P3)

Several of these are Teal re-implementing what the C layer could own; with upstream control, pushing the primitive down is the durable fix.

- **`[UPSTREAM]` quicksand/netns** hand-rolls `struct ifreq` in Teal with `string.pack`, hardcoding `IFNAMSIZ = 16` though `unix.IFNAMSIZ` exists, and guessing `IFREQ_UNION_SIZE = 24` with no C source. It also packs flags as **signed `i2`** (netns.tl:39,46) → any flag with bit `0x8000` raises "integer overflow". ◐ The `<i2`→`<I2` sign fix landed 2026-07-04 ([cosmic#431](https://github.com/whilp/cosmic/pull/431)); the durable fix — an upstream ifreq/`link_set_flags` (or rtnetlink) binding so the ABI layout lives in C, not a guessed Teal constant (`IFREQ_UNION_SIZE`/`IFNAMSIZ`) — remains open.
- **`[UPSTREAM]` quicksand/dial** runs a whole fork + pipe + poll + SIGKILL dance (~45 lines) purely because `cosmo.ResolveIp` is blocking with no deadline — an upstream resolve-with-timeout (or a non-blocking `getaddrinfo`-style binding) would delete the entire cross-process plumbing.
- **`[UPSTREAM]` codec** hex-decodes byte-by-byte in Teal while encoding in C — pure asymmetry from the missing `DecodeHex` binding/declaration (see §1.2). Add the decoder upstream.
- **fetch** re-parses URLs in Teal (`validate_url`) and hand-rolls dot-segment rejection with four patterns that risk bypass variants (`//`, backslash on Windows) — could delegate to the existing `cosmo.ParseUrl` (C) and `fs.normalize` rather than duplicating parse logic.

## Dimension 2 — Safety & correctness

### 2.1 Convention violations that throw or swallow (P0/P1)

- **P0 — SQLite iterators swallow step errors (sqlite.tl:132-173).** ✅ resolved 2026-07-04 ([cosmic#428](https://github.com/whilp/cosmic/pull/428)): iterators are now callable `Rows`/`Values` records that end only on `DONE` and expose the step error via `:err()`. *(original finding preserved below.)* `stmt:rows()`/`values()` return `nil` on any rc that is neither `ROW` nor `DONE`, so `SQLITE_BUSY`/`CORRUPT`/`CONSTRAINT` (from `RETURNING`) is indistinguishable from end-of-results: a query loop over a busy/corrupt DB silently terminates early and the caller believes it saw all rows. **Silent data loss.** Fix: iterators must return `nil` only on `DONE` and surface the error.
- **P1 — `time.timegm` throws (time.tl:153-175).** ✅ resolved 2026-07-04 ([cosmic#429](https://github.com/whilp/cosmic/pull/429)): `timegm` range-checks every field (leap-year-aware day) and returns `nil, err`; the `0`-sentinel parsers now propagate it. *(original finding preserved below.)* `MONTH_DAYS[m]` is nil for `m ≥ 13`, so `parse_date("2025-14-01")` (the pattern accepts 14-99) raises an arithmetic-on-nil error from library code; `month == 13` silently rolls into next January. Validate ranges; return `nil, err`.
- **P1 — closed sockets throw (net_socket.tl:79-203).** ✅ resolved 2026-07-04 ([cosmic#431](https://github.com/whilp/cosmic/pull/431)): every method except `close`/`closed` now guards `self.fd` and returns its error shape (`"socket closed"`). *(original finding preserved below.)* Every method except `close`/`closed` calls `unix.send(nil, …)` etc. after `close()`, raising from the C binding. `io.Handle` guards every method; `Socket` does not. Add `if not self.fd then return nil, "socket closed" end` guards.
- **P1 — SQLite use-after-close (sqlite.tl:250-259).** ✅ resolved 2026-07-04 ([cosmic#428](https://github.com/whilp/cosmic/pull/428)): `db:exec`/`prepare`/`last_insert_rowid`/`changes` now guard the `closed` flag. *(original finding preserved below.)* `closed` guards only `close()` itself; `db:exec` after `db:close` hits the freed raw handle (crash/throw), violating never-throw.

### 2.2 Error swallowing / resource issues (P1/P2)

- `child.tl`: `pipe:read` treats I/O errors as EOF (silent truncation, :65-78); `unix.pipe()` results unchecked so fd exhaustion crashes in the forked child (:216-232); `exec_fd` leaks on fork failure (:303-321); `wait()` **discards** the drained stdout/stderr it already collected (:380) and `read()` throws stderr away (:412) — there is no high-level way to capture both streams; `opts.stdin` written synchronously can deadlock on >pipe-buffer input and SIGPIPE-kills the parent (:423-426).
- `poll.tl:142-159`: `Poller:wait()` swallows poll errors (empty iterator == timeout == error) and there is no `EINTR` retry anywhere; combined with `child.tl:343`'s `wait(-1)` loop this can become a busy infinite loop.
- `sqlite.tl:159-173`: ✅ resolved 2026-07-04 ([cosmic#428](https://github.com/whilp/cosmic/pull/428)). `values()` uses `table.unpack(vals)` without bounds — a NULL first column terminates a generic-for early. Use `table.unpack(vals, 1, col_count)`.
- `fetch.tl:163-190`: `reader:lines()` drops read errors — a mid-body network failure looks like clean EOF (bad for SSE consumers).
- `shm.tl:66-68`: `mapshared` discards the mmap failure (typed to return only `Memory`) → nil crash later.
- Abandoning a `db:query()` iterator early leaks the prepared statement until GC (`query_one` was fixed, plain `query` was not; no `<close>` exposed).

### 2.3 Security (P0/P1)

- **P1 `[UPSTREAM]` — quicksand `capabilities().pledge/unveil` are effectively always `true` (init.tl:50-57).** `probe_nop` decides availability from an ENOSYS `Errno`, but `unix.pledge`/`unveil` are declared boolean-only (an upstream annotation gap — §1.1/§1.2), so `err` is always nil, the ENOSYS branch is dead, and the probe returns `true` on every failure. Preflight (`box/init.tl:160`) then never fires and a missing-pledge failure is deferred into the forked child. This is **resolved by the upstream `Errno`-return fix**, so it must be re-verified after Phase 0 rather than worked around locally.
- **P1 — proxy allowlist port fail-open (quicksand/proxy/rules.tl:38-47).** ✅ resolved 2026-07-04 ([cosmic#432](https://github.com/whilp/cosmic/pull/432)): a new `validate_key()` rejects a key whose port component is non-numeric / out-of-range / carries a stray extra colon, and `validate()` (called at box egress setup, `proxy.tl:123`) routes every key through it before `index()`. *(original finding preserved below.)* A malformed/typo'd port in an allowlist key (`"db:5432x"`) makes `tonumber` return nil → treated as `:*` (any port). `validate()` checks values, not keys. In a sandbox component this is fail-open. Validate keys: reject non-numeric / out-of-range / extra-colon.
- **P1 — `landlock.RW` silently includes EXECUTE (landlock.tl:50).** ✅ resolved 2026-07-04 ([cosmic#432](https://github.com/whilp/cosmic/pull/432)): `RW = READ | WRITE` now (EXEC dropped), with the doc corrected to say callers must OR in `EXEC` explicitly; `box/fs.tl`'s `fs.rw` mapping consequently no longer grants execute. *(original finding preserved below.)* `RW = READ | WRITE | EXEC` while the doc says "read + write"; consumed by `box/fs.tl:77` so `fs = { rw = {"/tmp"} }` grants execute on /tmp — a write+exec sandbox weakening the user never asked for. Drop EXEC (or rename `RWX` and document loudly).
- **P1 (verify) `[UPSTREAM]` — fetch TLS/redirects (fetch.tl).** TLS verification and redirect-following are delegated entirely to `cosmo.Fetch` (upstream C, mbedTLS) and are unverifiable from this repo; the wrapper exposes no cert/verify/redirect options and passes `opts.headers` unfiltered (CRLF-injection risk). The **TLS-verify default and redirect behavior are upstream concerns** — confirm the fork verifies certificates by default (redbean historically made this configurable) and expose the knobs through the binding; add CRLF validation on header names/values before the C call (in-repo). A silently non-verifying default here would make every `cosmic.fetch` user MITM-able with no API to fix it.
- **P2 — zip-slip via backslash (embed.tl:298-302).** ✅ resolved 2026-07-04 ([cosmic#432](https://github.com/whilp/cosmic/pull/432)): the guard is now a pure `embed.unsafe_entry()` that normalizes `\`→`/` before the `..` checks and rejects UNC (`\x`, `\\server\share`) and drive-letter (`C:\x`, `C:/x`, `C:x`) roots, with a unit test over backslash/drive-letter/safe cases. *(original finding preserved below.)* The extraction guard rejects absolute paths and `..` segments but `..\evil` passes; cosmic targets Windows. Reject `\` and drive-letter prefixes.
- **P2 — allocation-DoS** on `compress.inflate` trusting the attacker-controlled 4-byte size prefix (compress.tl:58-74) and on proxy `read_body` buffering unbounded `Content-Length` (http.tl:139-143). Add optional/max size caps.

### 2.4 Numeric / encoding correctness (P2)

- ✅ resolved 2026-07-04 ([cosmic#429](https://github.com/whilp/cosmic/pull/429)): the three `time` parsers now return `nil, err` (not `0`) on bad/out-of-range input, `parse_iso8601` accepts fractional seconds + `±HHMM`/`±HH` offsets, and the `DateTime` doc is corrected to `wday` 0-6 / `yday` 0-365. *(original finding preserved below.)* `time.parse_http`/`parse_date`/`parse_iso8601` return `0` (a valid epoch, 1970-01-01) on bad input instead of `nil, err`, and do no day/hour range validation (`"2025-01-99"` accepted → wrong epoch). `parse_iso8601` also **rejects fractional seconds** (time.tl:222-223) — which virtually every JSON API emits — and `±HHMM` offsets. `DateTime` doc claims `wday` 1-7 while cosmo `gmtime` returns 0-6 (likely doc bug).
- `url.parse_host("::1")` returns `host=":"`, `port=1` (greedy pattern mis-splits unbracketed IPv6) (url.tl:148-154).
- `ip.parse`/`resolve` return `-1` sentinels while `lookup` uses `nil, err` — mixed within one module.

## Dimension 3 — Error-handling consistency (cross-cutting)

`lib/cosmic/errno.tl` is a type declaration only — there is no shared stringify helper — so four conventions coexist:

1. `errno:doc()` behind a duck-typed guard — the dominant copy-pasted idiom (~10 sites: fs.tl, net_socket.tl, pledge.tl, proc.tl, signal.tl, unveil.tl). Produces `"Invalid argument"` (no errno name, no failing call/path).
2. `tostring(err)` → `"EINVAL/22/Invalid argument"` — a *different* user-visible format (landlock.tl, re.tl, env.tl).
3. Swallowed entirely into generic `"X failed: path"` — **`fs_ops.tl` does this in all 16 functions while importing `Errno` unused at line 5**; `fs.tl` is internally inconsistent (`mkdir`/`makedirs` give errno detail, `rmdir`/`chdir`/`stat` in the same module don't — directly violating "be consistent within a module").
4. `-1` sentinel leaked as API (ip.tl).

Also: `fs_ops.mkstemp` overloads its second return (path on success, error string on failure); no errno **constants** table (`ENOENT`, `EAGAIN`, …) is exported anywhere, so programmatic handling is impossible.

**Fix (P1):** give `errno.tl` a real `errno.str(err, prefix?): string` producing one canonical format (`"mkdir /x: EACCES: Permission denied"`), declare `__tostring`, export an errno-name constants table, and route all four idioms through it. Pairs naturally with the 1.1 generator fix.

## Dimension 5 — Test quality & coverage

The suite has real strengths (codec, string, fuzzy, envd, format, embed, and the quicksand *deny*-side proxy tests are genuinely adversarial). The systemic weaknesses:

### 5.1 Sandbox tests are structurally unfalsifiable in CI (P1)

CI runs `make ci` under landlock-make (pledge/unveil per rule), and nearly every sandbox test has an "outer sandbox may block this → skip" escape hatch (`if not ok then return end`, or accepting `ok|skipped|signal-death`). So **in the exact environment where they run automatically, most enforcement assertions silently degrade to no-ops**, and nothing alarms when everything skips. Add an "unexpectedly-everything-skipped" tripwire and a privileged, unsandboxed CI lane that actually exercises enforcement. **Pulled forward to Phase 1 as the step-8 prerequisite (2026-07-04 re-sequencing):** it gates whether the security fixes are testable in CI at all, so it must precede them rather than wait for Phase 2.

### 5.2 Highest-risk untested logic

- **`unveil` has no denial test** (unveil_test.tl:15-50 only checks the *allowed* path is readable; a completely non-functional unveil would pass).
- **`quicksand/proc.become_init` and `fork_pidns`** — the PID-1 supervisor (signal forwarding, zombie reaping, exit-code mapping `128+sig`) — are **completely untested** directly.
- **proxy allow-path never executes end-to-end** — the SSRF guard blocks all local upstreams, so `http.read_body`/`http.pump` are never run by any test; `serve.tl` has no test file at all.
- **`getpass`/`raw`/`restore`/termios paths never execute** (tty tests are tautological `type(x)=="boolean"` checks; both getpass tests can never fail).
- **`handle_check_format`** (the project's own format gate) has zero coverage of its whole diff-reporting path; **`--make`/`make.run`**, **`run.tl`** (traceback trimming + require hints), **`docs_lookup.tl`** (symbol-not-found UX), and the **`--examples`** chain are all zero-coverage.
- **`style.tl` has diverged from its tested twin `lint.tl`** — `check_call_after_define` (style.tl:62-73) counts only `function`/`end`, missing lint.tl's if/for/while/do/until depth handling, so `bin/make lint` and `cosmic --check-style` behave differently and no test can catch it.

### 5.3 Broad happy-path-only gaps

- **fs family:** `utimensat`/`futimens` untested over a doc-contradicting `nsecs or UTIME_OMIT` footgun; `fs_walk` silently swallows nonexistent-root and permission-denied-subdir errors (indistinguishable from empty) with no tests; `rmrf` failure path (used in every teardown) never observed; `join`'s documented absolute-path-reset semantics untested.
- **sqlite:** constraint violations, `SQLITE_BUSY` (no test opens two handles), use-after-close, nested transactions, and BLOB/NUL round-trips all untested — every tested error is a prepare-time syntax error.
- **rand:** length checks only, zero statistical sanity (a constant-but-nonrepeating generator would pass); **hash:** only one SHA-256 vector, no NIST empty/`"abc"` vectors, `argon2i`/`argon2d` variants never happy-path tested; **getopt:** the two canonical error paths (missing required arg, unknown-option contract) untested; **json:** no precision/nesting/`\uXXXX`/NUL tests; **zip:** `Appender:remove` wholly untested and the missing-entry `err` return never asserted.
- **Tautological tests** to rewrite: tty isatty×6, getpass×2, syslog blind calls, envd debug-count, quicksand `is_supported`×2, box run-shape, and all `ok|skipped|signal` subprocess tests.

### 5.4 Infrastructure

No coverage measurement exists. Add one (even a simple line-hit counter via the existing `instrument.tl` hook) and a per-PR summary. Enforce the cosmo-boundary lint rule (§1.7) as a test-quality gate.

**Build race — `$(doc_index)` vs its compiled-module prerequisites (P2, observed 2026-07-04).** The doc index depends on `$(doc_index_lua)` (the compiled `.lua` of every module), but under parallel `make` a regenerate triggered by a `.d.tl` change (e.g. a `cosmos` bump) can run before those `.lua` finish, silently emitting an index with only the `cosmo.*` `.d.tl` entries and **zero `cosmic.*` modules** — which fails `docs_test` with "0 topics". Clean builds are correct, so it surfaces only as an intermittent CI flake. Tighten the ordering (an order-only prerequisite, or generate the index from sources that don't race). Hit firsthand during the step-7 `cosmos` bump.

## Dimension 7 — Portability & performance

### 7.1 Portability (P1)

- **CI is Linux-only** (`pr.yml`, `release.yml`, `docs.yml` all `ubuntu-latest`). The five non-Linux fat-binary targets ship daily untested; `pledge_test.tl:15-30` would fail outright off Linux/OpenBSD, confirming multi-OS runs were never attempted. Add `macos-latest` + `windows-latest` smoke jobs (download/build the binary, run `cosmic -e`, `--docs`, and the fs/string/json tests).
- **`welcome.tl:20-30` mutates the running binary** — it zip-appends a "shown" marker to `arg[-1]`. On Windows the exe is locked so the banner reprints forever; on *any* OS the first tty run changes the binary's bytes, so release `SHA256SUMS` no longer verify and content-addressed deploys / AV signatures break. Store the marker in `$HOME/.config/cosmic/` (or `%LOCALAPPDATA%`).
- **`fs_path.tl` is pure-POSIX** — `normalize`/`abspath`/`relpath` test only `sub(1,1)=="/"`, never treat `\` as a separator, and `abspath("C:\\foo")` prepends cwd (garbage). Any Windows-user-supplied path breaks. Detect `%a:[/\\]` and leading `\\` as absolute, or document "POSIX paths only, even on Windows".
- Sandboxes fail gracefully but ignorably: `pledge`/`unveil` return `false, err` on the 4 non-Linux/OpenBSD platforms, and a caller who doesn't assert continues **completely unsandboxed** — document per-OS behavior and add an `available()` predicate like landlock's.
- `child.spawn` uses fork+execve (slow/fragile NT emulation) though `posix_spawn` wrappers exist unused; `fs_ops` discards errno everywhere (worst on Windows symlink privilege errors). No platform-support matrix exists anywhere — add one (module × OS: full/partial/error/untested) surfaced via `--docs guide.platforms`.

### 7.2 Performance (P1/P2)

- **P1 — `fetch.Reader:lines()` is O(n²) (fetch.tl:163-190):** `buffer = buffer:sub(newline_pos+1)` per line and `buffer .. chunk` per chunk re-copy the whole buffer; `sse.tl` builds on it, so long LLM-style streams blow up CPU. Use a scan-position index and compact lazily.
- **P2 — `benchmark.tl` measures `os.clock` (CPU, not wall):** any sleeping/IO benchmark accrues ~0 CPU time so the calibration loop grows `n` ×10 indefinitely (runaway); report wall time via `CLOCK_MONOTONIC`.
- **P2 — no benchmarks actually exist:** infrastructure is complete (`--benchmark`, Makefile target, `instrument.tl`) but **zero library modules define `Benchmark_*`**, so `make benchmark` is a no-op and there is no perf-regression tracking in CI. Seed benchmarks for the real hot paths (fuzzy, format, walk, fetch-lines, json, sqlite) and add a baseline diff.
- **P2 — the full Teal compiler loads eagerly on every startup** (main.tl:6), including `cosmic -e` and precompiled `.lua` scripts that never need it. Defer `require("tl")` into the compile/check/format/tl-script paths.
- P3: `fuzzy.find_similar` lacks a length-difference gate before the DP; `fs_walk` does one `lstat` per entry (could use `d_type`) and `walk` is unbounded recursion while `files()` is iterative.

**2026-07-04 — Phase 1 begins: the SQLite correctness bugs (step 5) landed** ([cosmic#428](https://github.com/whilp/cosmic/pull/428)), clearing the phase's P0:

- **Iterator error-swallowing (§2.1, P0 — silent data loss) fixed.** `Statement:rows()`/`values()` returned `nil` on *any* non-`ROW` step rc, so `SQLITE_BUSY`/`CORRUPT`/a `RETURNING` constraint failure was indistinguishable from a clean end-of-results and a loop over a busy/corrupt DB silently terminated early. Never-throw preserved throughout.
- **NULL-unpack (§2.2) fixed.** `values()` used unbounded `table.unpack(vals)`, which stops at the first hole, so a NULL first column dropped every remaining column; now bounded with `table.unpack(vals, 1, col_count)`.
- **SQLite use-after-close (§2.1) fixed.** `db:exec`/`prepare` (and the query/exec paths routing through `prepare`) plus `last_insert_rowid`/`changes` after `db:close()` hit the freed raw handle and threw; each now guards the `closed` flag and returns an error (or `0` for the numeric accessors).
