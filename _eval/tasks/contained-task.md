Build a sandboxed file-copy tool that demonstrates cosmic's containment story, using the `cosmic.sandbox` module (see the binary's docs for it). First create the fixture `testdata/in.txt` containing `hello` plus a trailing newline (6 bytes). The binary is `o/bin/copybox` (source `cmd/copybox/main.tl`). `copybox caps` prints exactly one line `fs=<true|false>` reporting whether this host can enforce a filesystem sandbox (via the module's availability query) and exits 0. `copybox <src> <destdir>` applies — before touching any file — a fail-closed filesystem sandbox whose allowlist grants read on the source file and write on the destination directory, then copies the source into `<destdir>/<basename of src>` and prints exactly `copied <n> bytes`; if the host cannot enforce the sandbox it must instead print `sandbox unavailable on this host` to stderr and exit 2 rather than copying unprotected. `copybox --deny-write <src> <destdir>` applies the same sandbox but deliberately omits the write grant on the destination directory, attempts the copy anyway, catches the resulting denial, prints to stdout a single line starting `denied: write to <destdir>` that also names the exact grant to add (the destination directory in the policy's `fs.rw` list), and exits non-zero without creating the destination file. Ship a test that runs the built binary in both modes (denial first, then the granted mode) and asserts both outcomes, and take the project to a green `ci` gate. This task runs on a Linux host where the OS enforces the sandbox; `caps` must nevertheless answer honestly wherever it runs.

## Acceptance facts

- `./cosmic --make build` produces an executable `o/bin/copybox`, and `cmd/copybox/main.tl` (or a module it requires) contains `require("cosmic.sandbox")` and a call to its `apply`.
- `./o/bin/copybox caps` exits 0 with stdout exactly `fs=true` on the eval host (Linux with Landlock; the value comes from the sandbox module's availability query, not a constant).
- `mkdir -p o/out && ./o/bin/copybox testdata/in.txt o/out` exits 0, stdout is exactly `copied 6 bytes`, and `o/out/in.txt` is byte-identical to `testdata/in.txt`.
- `mkdir -p o/denied && ./o/bin/copybox --deny-write testdata/in.txt o/denied` exits non-zero, stdout is one line starting `denied: write to o/denied` and containing `fs.rw`, and `o/denied/in.txt` does not exist afterwards — the denial was actually enforced, not simulated.
- The two modes run in separate processes (sandbox application is irreversible and process-wide), and the workspace contains a `*_test.tl` that spawns the built `o/bin/copybox` in `--deny-write` mode and then granted mode, asserting the denial output and the successful copy in that order.
- `./o/bin/copybox testdata/absent.txt o/out` exits non-zero with a message on stderr and empty stdout.
- `./cosmic --make ci` ends with `ci: PASS`.
