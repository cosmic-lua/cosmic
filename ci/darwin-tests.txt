# The test modules whose code under test takes a path only macOS takes,
# one a line from the checkout's root. On the macOS leg's gating runs,
# which stand on verdicts keyed by what each test declares, these run
# every time all the same (cosmic_ci/orchestration.tl's `darwin_words`):
# a Linux leg's verdict stands for the same key on macOS, but it never
# ran their macOS branch. The scheduled run's `--all` is the backstop
# for every other test. cosmic_ci/orchestration_test.tl holds each line
# to a test module of the tree.
#
# The core's platform-conditional C: darwin and aarch64 C is neither
# sanitized (orchestration.tl's `checked_suite` runs the checked core on
# linux-x86_64 alone) nor checked by `fix` (build/c/init.tl compiles
# each file for the host's target alone). Nor are build/c_functions.tl's
# Darwin exemptions tallied here: only a whole run, the scheduled one's,
# tallies which C functions a test entered.
#
# spawn by posix_spawn where Linux clones: its descriptors, directory,
# process group, mask and SIGPIPE given as file actions and attributes,
# the rest closed by POSIX_SPAWN_CLOEXEC_DEFAULT, exec's errno as
# posix_spawn's own, and the soft descriptor limit lowered around the
# call; confine, pledge, unveil, offline and subreaper refused ENOSYS
# (core/syscalls.c's `spawn_program`).
