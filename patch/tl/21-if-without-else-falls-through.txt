note: an `if` whose every block ends in a return still falls through when it has no `else`, so it does not itself end the block holding it. Marking it as ending one let an outer guard narrow past an inner branch that could fall through: `if e == nil then if flag() then return end end` narrowed e below it, e nil and flag() false notwithstanding. Below such an `if` the negation of its conditions still holds -- that is the only way past it -- so that narrow stays; only the claim that nothing follows it goes. 22 through 25 add more ways for a block to end, which would each inherit the same hole
--- find
            if all_return then
               node.block_returns = true
               self:infer_negation_of_if_blocks(node, node, #node.if_blocks)
            end
--- replace
            if all_return then
               -- Only an `else` closes the last way past: without one,
               -- control reaches the next statement when every
               -- condition is false.
               if not node.if_blocks[#node.if_blocks].exp then
                  node.block_returns = true
               end
               -- TODO: the negation below does not distribute over a
               -- condition that is an `or`: after `if p == nil or p == ""
               -- then return end`, p is still `string | nil`, though
               -- `not (a or b)` is `not a and not b`; two ifs narrow it.
               -- cosmic's own code splits such guards or defaults first
               -- (`local p = x.p or ""`).
               self:infer_negation_of_if_blocks(node, node, #node.if_blocks)
            end
--- end
