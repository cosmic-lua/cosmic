note: `metatable<T>`'s `__index` was `any`, so `setmetatable({}, { __index = { name = 1 } })` gave a `T` whose string field `name` read as the number 1. It is now `T | function(T, any): any...`, built from the record as written, type arguments included, so a generic `G<string>` is held to `v: string`. A table given as `__index` is checked against T's fields (`__index = R`, the class pattern, and `{}` or `{ name = "x" }` pass; `{ name = 1 }`, a record of another type and an unknown field are refused). What this closes is a table `__index`; a function `__index` is declared to return `any`, so what it serves is not checked, and neither is a metatable of a generic record's metamethods (`rec.meta_fields` is read only from a record that is not generic, as T is not applied to them). A `{string:any}` proxy, or a different record used as a base (`__index = Base` for `Dog is Base`), is refused because neither can be shown to serve T's fields: write the proxy as a function `__index` (`function(t: R, k: any): any`), or copy the base's fields into the record. The other metamethods are checked against T's declared ones, a literal and a variable alike, since 47d requires a variable passed to be typed `metatable<T>`. The check is made where the type is applied, so `local mt: metatable<R> = {...}` is held to it as `setmetatable(t, {...})` is
