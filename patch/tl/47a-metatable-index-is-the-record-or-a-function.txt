note: `metatable<T>`'s `__index` was `any`, so `setmetatable({}, { __index = { name = 1 } })` gave a `T` whose string field `name` read as the number 1. It is now `T | function(T, any): any...`: a table literal given as `__index` is checked against T's fields (`__index = R`, the class pattern, and `{}` or `{ name = "x" }` pass; `{ name = 1 }`, a record of another type and an unknown field are refused), and a function takes the record and the key. A `{string:any}` proxy or a different record used as a base is refused too, because neither can be shown to serve T's fields: write the proxy as a function `__index` (`function(t: R, k: any): any`), or copy the base's fields into the record. The other metamethods are checked against T's declared ones already (`__call` among them), a literal and a variable alike, since 47d requires a variable passed to be typed `metatable<T>`. The check is made where the type is applied, so `local mt: metatable<R> = {...}` is held to it as `setmetatable(t, {...})` is
