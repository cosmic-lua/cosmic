file: ext/misc/compress.c
note: uncompress() allocates the length its argument's prefix claims, up to 2^35-1 bytes, before it reads the stream: a five-byte blob fails its statement with "out of memory", and a claim under SQLite's cap allocates that much. The function is SQLITE_INNOCUOUS, so a view or trigger in a database a caller opens can call it. Deflate writes no more than 1032 bytes for each byte of stream, so a claim past that is not what the stream holds: this answers NULL for it, as uncompress() does for any other stream it cannot read, before allocating anything. Upstream has no such bound as of 3.54.0.
--- find
  pOut = sqlite3_malloc64( (sqlite3_uint64)nOut+1 );
--- replace
  if( nOut > (sqlite3_uint64)(nIn-i)*1032 ) return;
  pOut = sqlite3_malloc64( (sqlite3_uint64)nOut+1 );
--- end
