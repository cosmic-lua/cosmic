note: rtreecheck() and an R*Tree's part of PRAGMA integrity_check walk the tree from its root, following each cell of a node above the leaves to a child, as deep as the root's depth header says, and read each node they reach. The nodes are a file's bytes: a depth header that lies, or cells that point back at nodes already read, make the walk read and scan the same nodes again and again. A root that claims 65535 cells each pointing at itself, beside padding rows in %_node, takes minutes for a file of a megabyte, and a lying depth doubles the work at each of up to 40 levels; cosmic's SQLite has no progress callback to stop either. This record and the three after it keep the set of nodes the walk has read, refuse a second read of any node and any node number below 1, and report each: each node is scanned once, and its cells are no more than its bytes allow, so the check's work is bounded by the bytes of the distinct nodes it reads. The set grows with the nodes read, 16 to 32 bytes each, never sized from %_node, which a file may make a view. A tree whose every node is reached once, as a whole tree's is, from node numbers of 1 and above, as SQLite gives them, reads the same and reports the same. Upstream walks without such a set as of 3.54.0.
