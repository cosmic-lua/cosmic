note: A Lua function's call of a C function runs the pending finalizers first, unless the function is one lua_setinert named (patch/lua/26-finalizers-at-c-calls-inert-gc.txt): the checker counts any other call as one that may run any code. Only a call the VM makes for OP_CALL and OP_TAILCALL runs them: a C function's own lua_call or lua_pcall of another runs none, so a binding that holds a library's state across one (core/xml.c's appends) is never re-entered by a finalizer, and nor is a C metamethod the VM calls for an index or an operator, which the checker counts as no call. A Lua function runs them in luaD_precall (patch/lua/23-finalizers-at-calls-run.txt).

/*
** Whether the VM runs the pending finalizers before it calls 'f' for
** OP_CALL or OP_TAILCALL: 'f' is a C function lua_setinert did not name
** (patch/lua/31-finalizers-at-c-calls-run-call.txt).
*/
static int runsfinalizers (const TValue *f) {
  switch (ttypetag(f)) {
    case LUA_VLCF: return !luaC_inert(fvalue(f));
    case LUA_VCCL: return 1;
    default: return 0;
  }
}
