note: the fast literal/length path's second lookup fails on an empty slot, as TINFL_HUFF_DECODE does (see 01-invalid-code-decode.txt), in a state of its own (55), clear of every index tinfl uses. 01 alone ends the hang: without this, the fast path writes literal 0 for an empty slot until the window's end, and the slow path's lookup, which 01 checks, then fails. This only makes the failure prompt, skipping up to 32 KB of wasted writes; no test can tell it apart from 01 alone, since the output is dropped with the failure.
